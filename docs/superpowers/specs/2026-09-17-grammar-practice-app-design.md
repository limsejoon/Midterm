# 중등 국어 문법 대체 문제 학습 앱 — 설계 문서

- 날짜: 2026-09-17
- 상태: 승인 대기 (사용자 리뷰 전)

## 배경 / 목적

아이가 문제집을 풀 때, 문제를 이해해서 푸는 것이 아니라 답을 외우거나 문제의
생김새(위치, 보기 배열 등)로 골라버릴 수 있다는 우려가 있음. 같은 문법 개념을
다루되 지문/보기가 다른 "대체 문제"를 자동으로 만들어서 반복 학습시키면 이
문제를 줄일 수 있음.

- 대상 과목: 중등 국어 문법 (품사, 문장성분, 높임법, 사동/피동 등)
- 사용자: 가정 내 개인 용도 (부모가 문제 입력/확인, 아이가 풀이)
- 배포: 개인용 Vercel 프로젝트, 로그인 없이 단일 접근

## 아키텍처 개요

```
[부모: 폰 카메라로 문제집 페이지 촬영]
        │  업로드 (이미지)
        ▼
[Next.js 웹앱 (Vercel)]
        │  1) 멀티모달 AI 호출 → 문제/보기/정답/문법개념 추출
        ▼
[추출 결과 확인 화면 (부모)]
        │  2) 부모가 확인/수정 후 저장
        ▼
[원본 문제 DB 저장 (Neon Postgres)]
        │  3) AI에게 "같은 개념의 대체 문제 N개 생성" 요청
        ▼
[대체 문제 DB 저장] ──▶ [풀이 화면 (아이)] ──▶ [채점] ──▶ [풀이 기록 DB 저장]
                                                              │
                                                              ▼
                                                    [통계/기록 조회 화면]
```

스택:
- **Next.js (App Router)**, Vercel 배포
- **Vercel AI Gateway**를 통한 AI SDK 호출 (모델 문자열로 provider 추상화)
- **Neon Postgres** (Vercel Marketplace) + Drizzle ORM
- 이미지 자체는 저장하지 않음 — 추출된 구조화 데이터만 보관 (프라이버시/스토리지 절약)

## 데이터 모델

```
concepts
  id, name (예: "부사와 관형사 구분"), created_at

problems  -- 원본 문제 (사진에서 추출 후 부모 확인 완료)
  id, concept_id, type (multiple_choice | short_answer | ox),
  question_text, choices (jsonb, nullable), correct_answer,
  source_note (예: "3단원 12번"), created_at

variants  -- AI가 생성한 대체 문제
  id, problem_id (원본 참조), concept_id, type,
  question_text, choices (jsonb, nullable), correct_answer,
  created_at

attempts  -- 아이의 풀이 기록
  id, variant_id, submitted_answer, is_correct,
  graded_by (exact | ai_judged), solved_at
```

`concept_id`를 attempts까지 조인해서 "개념별 정답률" 통계를 낼 수 있음.

## 주요 흐름

### 1. 문제 입력 (사진 → 구조화 데이터)
- 부모가 이미지 업로드
- 멀티모달 AI 호출: 문제 텍스트, 보기(있다면), 정답, 문법 개념 태그를 JSON으로 추출
- 결과를 폼에 채워서 확인 화면에 표시 — 모든 필드 수정 가능
- 부모가 "저장"하면 `problems` 테이블에 기록 (여기서 처음 DB에 남음, 이미지는 버림)

### 2. 대체 문제 생성
- 저장된 원본 문제 + 개념을 프롬프트에 넣어 AI에게 N개(기본 3개) 생성 요청
- AI는 문제마다 `type`을 자유롭게 선택 (객관식/단답형/OX 중 개념 테스트에 적합한 형식)
- 객관식인 경우 보기 순서를 매번 섞어서 저장
- 생성 결과를 `variants`에 저장 (자동 저장, 부모 확인 단계 없음 — 원본만 확인하면 충분하다고 판단)

### 3. 풀이 & 채점
- 아이가 아직 안 푼 variant를 화면에서 풀이 (객관식은 버튼 선택, 단답형/OX는 입력)
- 채점 로직:
  - `multiple_choice`, `ox`: 저장된 정답과 그대로 비교 → `graded_by: exact`
  - `short_answer`: 공백/기호 정규화 후 정확히 비교 → 실패 시 AI에게 "의미상 정답과 같은가" 판단 요청 → `graded_by: exact | ai_judged`
- 결과와 함께 정답/해설(선택) 즉시 표시
- `attempts`에 기록 저장

### 4. 기록/통계 조회
- 최근 풀이 목록, 개념별 정답률, 자주 틀리는 개념 하이라이트
- (이번 스펙 범위: 간단한 목록 + 개념별 정답률 표. 상세 대시보드는 이후 확장)

## 에러 처리

- 이미지에서 AI가 문제를 제대로 못 읽으면 → 확인 화면에 "인식 실패, 직접 입력해주세요" 안내 + 빈 폼 제공 (수동 입력 폴백)
- 대체 문제 생성 AI 호출 실패 → 재시도 버튼 제공, 실패 원인은 화면에 노출하지 않고 로그만 남김
- AI 단답형 채점 호출 실패 → 정규화 비교 결과로만 판정하고 "자동 채점(AI 확인 불가)"로 표시

## 테스트 전략

- 문제/대체문제/채점 관련 핵심 로직(정규화 비교, 통계 집계 쿼리)은 단위 테스트
- AI 호출부는 실제 API 대신 mock 응답으로 흐름(추출 → 확인 → 생성 → 채점) 통합 테스트
- 수동 확인: 실제 문제집 페이지 사진으로 입력 → 확인 → 대체 문제 생성 → 풀이까지 한 번 직접 실행해서 확인

## 범위 밖 (이번 스펙에서 제외)

- 로그인/다중 사용자
- 문제 이미지 원본 보관
- 상세 대시보드/그래프
- 다른 과목 지원 (국어 문법 외)
